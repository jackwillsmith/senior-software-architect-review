# ATAM 四类点 · 判定信号词与话术模板

> 私人复习文件（`.study/`）。对应案例题"识别 2 个敏感点、2 个权衡点、2 个风险点、2 个非风险点"（10 分）。

---

## 一、先理解本质：这是**两个不同的维度**

| 维度 | 回答的问题 | 涉及类型 |
|---|---|---|
| **维度 A：影响几个属性** | 这个决策动了，会影响几个质量属性？ | 1 个 → **敏感点**；≥2 个且方向相反 → **权衡点** |
| **维度 B：有没有隐患** | 这个决策会不会出问题？ | 有隐患 → **风险点**；已验证 → **非风险点** |

> ⚠️ **重要**：一个决策**可以同时**是两个维度的类型。
> 例如："引入缓存提升性能但降低一致性，且缓存击穿未做防护" —— 既是**权衡点**，也是**风险点**。
> 考试若要求四选一，按"**题干最突出的特征**"归类（见第四节判定顺序）。

**权衡点 ⊂ 敏感点**：权衡点本质是"影响多个属性的敏感点"，即权衡点也是敏感点的一种。

---

## 二、信号词速查（看到这些词就往对应类型想）

### 🔵 敏感点（Sensitivity Point）
> 本质：**对某一个质量属性影响显著的关键决策**（中性，不一定有毛病）

**信号词**：
- "为达成……目标，我们采用……"
- "该决策**直接决定**了……"
- "……是达成……的**关键**"
- "**直接影响**……指标"
- 题干先给指标（如"切换 < 30s"），紧接着给出支撑它的决策

### 🟣 权衡点（Trade-off Point）
> 本质：**影响多个质量属性且此消彼长**

**信号词**：
- "**既**……**又**……"
- "**提升** X **但降低** Y"
- "以**牺牲**……为代价"
- "**同时影响**……和……"
- "……换来了……" / "……的代价是……"
- ⭐ 最可靠：**同一句话里出现两个质量属性，方向相反**

### 🔴 风险点（Risk）
> 本质：**可能引发问题的决策**（隐患、未验证、单点）

**信号词**：
- "**可能**导致……"
- "存在**隐患** / **风险**"
- "**尚未验证** / 未做压测 / 未在生产验证"
- "**单点**" / "**唯一**"
- "容量**未知** / 峰值数据量**未知**"
- "缺乏……机制 / 未接入……"
- "如果……则……"（条件式隐患描述）

### 🟢 非风险点（Non-Risk）
> 本质：**经分析确认可靠的决策**（成熟、已验证）

**信号词**：
- "**已验证** / 已压测 / 已上线"
- "业界**成熟**方案"
- "已有**充分**案例"
- "**CNCF 毕业**项目 / 生产级方案"
- "**标准**协议 / 规范"
- "无技术不确定性"

### ⚪ 不纳入 ATAM
- "与系统架构**无关**"（如给办公室加咖啡机）

## 三、话术模板（答题直接用，这是采分点）

### 敏感点
> "**XX 是敏感点**，因为它**直接决定**了【质量属性】目标（【具体指标】）能否达成。"

**示例**：
"KubeEdge 采用 1 主 2 从部署是敏感点，因为它直接决定了边缘节点在单点故障时的可用性目标（年可用性 99.95%、故障切换 < 60 秒）能否达成。"

### 权衡点
> "**XX 是权衡点**，它**同时影响**【属性A（+）】和【属性B（−）】。"

**示例**：
"全链路 HTTPS + AES-256 加密是权衡点，它同时影响安全性（+，防中间人攻击、满足等保要求）和性能（−，TLS 握手与加解密带来约 10% 的 CPU 开销）。"

### 风险点（加分技巧：附缓解战术）
> "**XX 是风险点**，存在【单点 / 未验证 / 容量未知】隐患，**可能**导致【后果】。**建议引入【某战术】将其转化为非风险点。**"

**示例**：
"促销服务作为单体保留且未接入熔断限流是风险点，存在被异常流量击穿后波及订单服务的隐患，可能威胁可用性目标。建议引入 Sentinel 熔断 + 只读副本拆分，将其转化为非风险点。"

### 非风险点
> "**XX 是非风险点**，采用【业界成熟方案 / 已验证】，已在【某场景】充分验证，无技术不确定性。"

**示例**：
"Kubernetes 跨 3 可用区部署 + Istio 流量治理是非风险点，二者均为 CNCF 毕业项目，生产级成熟方案，无技术不确定性。"

## 四、实用判定顺序（考试四选一时按这个走）

```
看这个决策描述：
│
├─ ① 它跟系统架构有关吗？
│      无关 → 不纳入 ATAM（不要写成非风险点！）
│
├─ ② 描述里有"可能 / 尚未 / 单点 / 未知 / 隐患"吗？
│      有 → 【风险点】
│
├─ ③ 描述里同时出现两个属性、方向相反吗？
│      有 → 【权衡点】
│
├─ ④ 描述说它对某个属性影响显著/是关键/直接决定？
│      有 → 【敏感点】
│
└─ ⑤ 描述说它成熟/已验证/是标准方案吗？
       有 → 【非风险点】
```

> 💡 若一个决策同时符合 ② 和 ③（既是权衡点又有隐患），**先答风险点并在理由里说明它也影响多属性**，或按题干侧重选择——理由写充分即可得分。

## 五、易混对比（三个最容易错的）

### ① 敏感点 vs 风险点（最高频混淆）
| | 敏感点 | 风险点 |
|---|---|---|
| 情感色彩 | **中性**（只是"重要"） | **负面**（"有毛病"） |
| 例子 | "主备切换 < 30s"（正面关键决策） | "MQ 单点且未持久化"（隐患） |
| 判断法 | 问："它是达成目标的关键吗？" | 问："它有没有隐患？" |

### ② 敏感点 vs 权衡点
| | 敏感点 | 权衡点 |
|---|---|---|
| 影响属性数 | **1 个** | **≥2 个**，方向相反 |
| 例子 | "CDN 分发 → 静态响应快"（只影响性能） | "缓存 → 性能↑但一致性↓" |

### ③ 非风险点 vs 无关项
| | 非风险点 | 无关项 |
|---|---|---|
| 是否参与评估 | **参与**（是架构决策且确认无问题） | **不参与**（与架构无关） |
| 例子 | "Kafka 集群 3 主 3 从" | "给办公室加咖啡机" |
| 处理方式 | 答"非风险点" | 明确排除，不归入四类点 |

## 六、万能高分句（背下来直接用）

- "该架构决策是**敏感点**，因为它**直接决定**了【可用性/性能】质量目标的达成。"
- "【HTTPS 全链路加密】是**权衡点**：**提升了安全性**但**增加了约 10% 的 CPU 开销**。"
- "**识别出该风险点**后，建议引入【Sentinel 熔断 / RocketMQ 持久化 / 多活部署】战术，将其**转化为非风险点**。"
- "依据 **ATAM 第 5 步（效用树）**，【性能-吞吐 (H, H)】为最高优先级，应在架构决策中优先保障。"

## 七、自测清单（拿到题干后逐条问）

1. 有没有"可能/尚未/单点/未知"？→ **风险点**
2. 有没有"提升 X 但降低 Y"？→ **权衡点**
3. 有没有"直接决定/关键/为达成……"？→ **敏感点**
4. 有没有"成熟/已验证/标准"？→ **非风险点**
5. 有没有"与架构无关"？→ **排除，不作答**
6. 每条判断后面**必须跟一句"因为……"**（不写理由扣分）
7. 风险点**尽量附缓解战术**（额外加分）
