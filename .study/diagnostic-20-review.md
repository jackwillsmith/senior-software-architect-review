## §4 软件工程

### 1. 用例图的主要元素不包括 → 正确答案 **C（类）**　【你答 D ✗】

**知识点**：用例图核心四元素 = **参与者（Actor）+ 用例（Use Case）+ 系统边界 + 关系**。
关系又含 4 种：关联、包含 `<<include>>`、扩展 `<<extend>>`、泛化。
**"类"是类图的元素**，不属于用例图。

**干扰项辨析**：D（系统边界）**是**用例图元素——那个画系统范围的方框。你错在把"系统边界"当成了外来物。

> 🪝 **钩子**："用例图 = 谁（参与者）用系统做什么（用例），框起来看边界（系统边界）。**类进类图，不进用例图。**"

### 2. 软件测试分类描述错误的是 → 正确答案 **C**　【你答 C ✓】

**知识点**：
- 按是否看内部结构：**黑盒**（功能/规约驱动）vs **白盒**（结构/路径驱动）
- 按阶段：**单元 → 集成 → 系统 → 验收**
- **执行者与盒子颜色无关**：黑盒常由独立测试人员/用户做；白盒由开发/测试工程师做
- **α 测试**：开发方场地、受控环境、用户参与；**β 测试**：用户实际环境、收集反馈

**C 错在哪**：说"黑盒只能由开发人员执行、白盒由用户执行"——把执行者与盒子类型错误绑定。

> 🪝 **钩子**："**黑盒看功能，白盒看代码，谁做都行**。α 在开发方场地（Alpha 在自家），β 在用户现场（Beta 出门）。"

### 3. 净室软件工程描述错误的是 → 正确答案 **D**　【你答 A ✗】

**知识点**：净室（Cleanroom）软件工程：
- 用**形式化规约 + 正确性验证**防止缺陷被引入（不是事后测试发现）
- 开发阶段**不做单元测试**，靠正确性验证
- 用**统计测试**估计可靠性
- 适用：**航天、医疗、核电、国防**（可靠性极高要求）
- **不适合**：需求频繁变化、快速迭代的互联网项目

**D 错在哪**："主要适用于需求频繁变化的互联网项目"——恰好相反。净室代价是成本极高、需数学背景人员。

> 🪝 **钩子**："**净室 = 无尘室 = 不许进灰尘 = 不许进 bug**，只在航天医疗核电这类'错一次就完蛋'的地方用。"

### 4. 螺旋模型的最大特点 → 正确答案 **B**　【你答 B ✓】

**知识点**：Boehm 1988 螺旋模型，每次螺旋四象限：
**目标设定 → 风险分析 → 开发与验证 → 计划下一阶段**
- 灵魂是**风险分析**：每轮判断"是否继续"
- 适用：**需求复杂、技术新、不确定性高、规模大**（大型航天、政务）
- 代价：重型流程，不适合小项目

**干扰项**：A 快速交付=敏捷/原型；C 摒弃文档=错（螺旋文档很重）；D 小项目=错。

> 🪝 **钩子**："**螺旋 = 一圈一圈往上爬，每圈先做'风险体检'** —— 大项目才需要体检。"

## §6 系统架构

### 5. ABSD 六个阶段顺序 → 正确答案 **A**　【你答 A ✓】

**知识点**：ABSD（Architecture-Based Software Development）六阶段：
**① 架构需求 → ② 架构设计 → ③ 架构文档化 → ④ 架构复审 → ⑤ 架构实现 → ⑥ 架构演化**
- 核心思想：**架构先行**，自顶向下、需求驱动，架构指导后续设计与实现
- **复审在实现之前**——此时发现问题成本最低
- 输出物：架构规约 SAD

**干扰项**：B 顺序全乱；C 是通用瀑布流程；D 缺阶段。

> 🪝 **钩子**："**需求 → 设计 → 文档 → 复审 → 实现 → 演化**；口诀'**求设文审现演**'。复审卡在实现前，因为**改图纸比拆楼便宜**。"

---

### 6. 4+1 视图中的"+1" → 正确答案 **C（场景视图/用例视图）**　【你答 C ✓】

**知识点**：Kruchten 1995 提出 4+1 视图：
| 视图 | 关注 |
|---|---|
| 逻辑视图 | 面向**最终用户的功能需求**（类/对象/包结构） |
| 开发视图 | 代码包/模块的**物理组织**（开发期） |
| 进程视图 | **并发、性能、同步** |
| 物理视图 | **部署节点、网络拓扑** |
| **场景视图（+1）** | **用关键用例串联验证其他 4 个视图** |

**"+1"的作用**：选关键用例，在其余 4 个视图中跑通——若某用例在物理视图上延迟超标，则架构要调。

> 🪝 **钩子**："**逻辑看功能，开发看包，进程看并发，物理看部署，场景（+1）把四个串起来验一遍** —— 场景视图是'总检查员'。"

---

### 7. 微服务架构描述错误的是 → 正确答案 **C**　【你答 D ✗】

**知识点**：微服务正确特征 = 单一职责、轻量通信（REST/MQ）、**独立部署**、每个服务**独立数据库**、去中心化治理、围绕**限界上下文（Bounded Context）**划分。

**C 错在哪**："服务粒度应尽可能小"——**粒度不是越小越好**。过小会导致网络开销、一致性复杂度、运维复杂度暴增。

**你选的 D（去中心化治理）是对的描述**，不该选。

> 🪝 **钩子**："**微服务'够小'就行，不是'越小越好'** —— 拆过头 = 网络调用满天飞 + 分布式事务噩梦。粒度看**限界上下文**（业务边界），不看代码行数。"

---

### 8. 缓存击穿的根本原因 → 正确答案 **B**　【你答 B ✓】

**知识点**——缓存三大问题必须区分：
| 问题 | 特征 | 解法 |
|---|---|---|
| **穿透** | 查**不存在**的 key，全打到 DB | 布隆过滤器、缓存空值 |
| **击穿** | **单个热点 key 突然失效**，高并发瞬间打 DB | 热 key 不过期、互斥锁、逻辑过期 |
| **雪崩** | **大量 key 同时过期**或缓存宕机 | TTL 加随机偏移、Redis 高可用、限流降级、多级缓存 |

**干扰项**：A=雪崩；C=雪崩（缓存整体宕机）；D 是结果不是原因。

> 🪝 **钩子**："**穿透=查不存在的（穿过去了）；击穿=一个热 key 被打爆（单点击穿）；雪崩=一片 key 同时死（大面积塌方）。**"

## §1 计算机系统

### 9. MIPS 计算 → 正确答案 **C（400）**　【你答 C ✓】

**知识点**：**MIPS = 主频 / CPI**（每指令平均时钟周期数）
本题：2000 MHz ÷ 5 = **400 MIPS**
- 相关公式：**CPU 时间 = 指令数 × CPI / 主频**
- MIPS 只反映运算速度，不能跨指令集比较

> 🪝 **钩子**："**MIPS = 主频 ÷ CPI**（MHz 除周期数）。2GHz、5 周期 → 400。"

---

### 10. 流水线总时间 → 正确答案 **C（(k+n−1)·t）**　【你答 C ✓】

**知识点**：n 条指令、深度 k、周期 t：
- **总时间 = (k + n − 1) · t**
- 推导：第一条需 k 个周期出结果，之后每个周期完成一条 → (k−1) + n
- 加速比 S = n·k / (k+n−1)，**k 越大加速比越接近 k，但流水线越深，冲突/开销越大**

> 🪝 **钩子**："**第一条填满流水线要 k 拍，后面每条 1 拍**：k + n − 1。"

---

### 11. Cache 地址映射描述错误的是 → 正确答案 **D**　【你答 A ✗】

**知识点**：
| 映射方式 | 位置约束 | 命中率 | 硬件成本 |
|---|---|---|---|
| 直接映射 | 每块**唯一位置** | **低** | 简单便宜 |
| 全相联 | 任意位置 | **最高** | 复杂昂贵 |
| 组相联 | 组内任意 | 折中 | 折中 |

**D 错在哪**："全相联映射命中率低"——**恰好相反，全相联命中率最高**（但硬件最贵）。

**你选的 A（直接映射每块唯一位置）是对的**，不该选。

> 🪝 **钩子**："**全相联=随便放=命中率最高但最贵；直接映射=只准放一个坑=最便宜但命中率低**；组相联居中。"

---

### 12. 页式存储地址转换 → 正确答案 **D（页表 + 快表）**　【你答 D ✓】

**知识点**：
- **页表**：完成页号 → 物理块号映射
- **快表 TLB**：缓存最近使用的页表项，加速转换（否则每次访存要读两次内存）
- 段式存储用**段表**；段页式两者都用
- 相关：**抖动（Thrashing）**= 频繁缺页换页

> 🪝 **钩子**："**页表查地址，快表（TLB）抄近路** —— 两个一起用才快。"

## §7 质量属性

### 13. ATAM 全称 → 正确答案 **A（架构权衡分析方法）**　【你答 C ✗】

**知识点**：**ATAM = Architecture Tradeoff Analysis Method**，SEI（卡内基梅隆软件工程研究所）提出的架构评估方法。
- 核心产出：**风险点、非风险点、敏感点、权衡点**四类点
- 相关方法：SAAM（更早，侧重可修改性）、CBAM（成本收益）

**你选的 C（系统可靠性评估方法）**——ATAM 评估的是**多质量属性权衡**，不只是可靠性。

> 🪝 **钩子**："**ATAM 的首字母 A = Architecture，T = Tradeoff（权衡）** —— 名字里就写着'架构权衡'。看到 'Tradeoff' 就选它。"

---

### 14. 敏感点的定义 → 正确答案 **B**　【你答 B ✓】

**知识点**：**敏感点（Sensitivity Point）**= 为实现某个质量属性而**重点分析**的架构决策——即"改动它会**显著影响某个质量属性**"的点。**只涉及单个属性**。

**干扰项**：A（最关键组件）≠敏感点；C（可能崩溃）像风险点；D（性能瓶颈）太窄。

> 🪝 **钩子**："**敏感 = 对某一个属性特别'敏感'**（碰它就动那个属性）。**只撩一个属性的叫敏感点，同时撩两个以上的叫权衡点。**"

---

### 15. 权衡点的定义 → 正确答案 **A**　【你答 A ✓】

**知识点**：**权衡点（Trade-off Point）**= 对某个质量属性有利、对另一个质量属性不利的架构决策，是**敏感点的特例**（影响多属性且此消彼长）。
- 经典例：加缓存 → 性能↑、一致性↓；加加密 → 安全↑、性能↓

**干扰项**：B 架构师分歧≠权衡点；C 成本最高≠；D 与性能无关≠。

> 🪝 **钩子**："**权衡点 = '一升一降'** —— 有得必有失的那个决策。题干出现'XX 提升但 YY 下降' → 直接写权衡点。"

## 快分点：IP / 数据库 / 安全

### 16. 我国专利申请原则 → 正确答案 **B（先申请制）**　【你答 A ✗】

**知识点**：我国（及绝大多数国家）专利采用**先申请制**——同样的发明创造，专利权授予**最先申请**的人，**不是最先发明的人**。
- 美国历史上曾用"先发明制"，2013 年后也改为先申请制
- **同样的发明创造只能授予一项专利权**

**你选的 A（先发明制）**——那是美国旧制度，也是软考经典陷阱。

> 🪝 **钩子**："**专利比谁'先交表'，不比谁'先想出来'** —— 先申请制。想出来没用，**递交才作数**。"

### 17. 不能获得专利保护的是 → 正确答案 **C（纯数学算法/智力活动规则）**　【你答 C ✓】

**知识点**：**不授予专利权**的对象：
- 科学发现
- **智力活动的规则和方法**（纯数学算法、游戏规则）
- 疾病的诊断和治疗方法
- 动物和植物品种
- 原子核变换方法获得的物质

**保护路径**：纯算法要保护 → 靠**商业秘密**（不公开）或**著作权**（保护代码表达），**不能靠专利**。

**A/B/D 都能授权**：芯片电路、生产工艺、机械结构 ✓ 分别对应发明/实用新型。

> 🪝 **钩子**："**算法思想不受专利保护**（专利保护的是'技术方案'不是'纯脑力规则'）。算法想保密 → 商业秘密；代码想保护 → 著作权。"

### 18. 候选键判定 → 正确答案 **A（A）**　【你答 C ✗】

**知识点**：求**属性闭包**：
F = {A→B, B→C, A→D}
- A+ 先含 A → 由 A→B 得 B → 由 B→C 得 C → 由 A→D 得 D
- **A+ = {A, B, C, D}** = 全部属性 → **A 是候选键**（且是唯一候选键）

**方法**：候选键必须能**推导出全部属性**。只在左边出现、不在右边出现的属性，必然是候选键的组成部分。

**你选的 C（AC）**——A 单独就够了，加 C 是冗余（不是"最小"）。

> 🪝 **钩子**："**候选键 = 能推出所有属性的最小集合**。做法：从 A 出发一路推，能推出全部 → A 就是键。**加属性除非必要，否则不算最小。**"

### 19. 范式判定 → 正确答案 **B（2NF）**　【你答 B ✓】

**知识点**：
- **1NF**：属性不可再分
- **2NF**：1NF + **消除非主属性对候选键的部分依赖**
- **3NF**：2NF + **消除传递依赖**
- **BCNF**：每个决定因素都包含候选键

本题：候选键 A（**单属性**）→ **不可能有部分依赖** → 满足 2NF；
但存在 **A→B→C 传递依赖** → 不满足 3NF。

> 🪝 **钩子**："**单属性键自动过 2NF**（没东西可'部分'依赖）。**有 A→B→C 这种'接力'就是传递依赖 → 卡在 2NF，升不到 3NF。**"

### 20. STRIDE 中的 T → 正确答案 **B（Tampering 篡改）**　【你答 B ✓】

**知识点**：**STRIDE** 六类威胁：
| 字母 | 威胁 | 破坏的属性 |
|---|---|---|
| **S** | Spoofing 冒充 | 认证 |
| **T** | **Tampering 篡改** | 完整性 |
| **R** | Repudiation 抵赖 | 不可否认性 |
| **I** | Information disclosure 信息泄露 | 机密性 |
| **D** | Denial of service 拒绝服务 | 可用性 |
| **E** | Elevation of privilege 权限提升 | 授权 |

**干扰项**：A Threat 是"威胁"的泛称；C Timing 是侧信道攻击；D Trust 不在 STRIDE 中。

> 🪝 **钩子**："**STRIDE = 冒充、篡改、抵赖、泄露、拒绝服务、提权** —— 前六个字母正好是这六类威胁的首字母。T 就是 Tampering（**tamper = 动手脚**）。"
