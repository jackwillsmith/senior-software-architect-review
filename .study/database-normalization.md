## 零、符号约定（读题前提）

### R(A, B, C, D) 是什么？

- **R = 关系模式（Relation Schema）** = 一张表的**表头定义**（只有列，没有数据）
- **A、B、C、D = 属性（列）**，属性集记作 **U = {A, B, C, D}**
- **F = 函数依赖集** = 定义在这张表上的约束规则
- 全句读作："关系模式 R，属性集为 {A,B,C,D}，约束集为 F"

等价于 SQL 里的 `CREATE TABLE R (A, B, C, D)` + 若干依赖约束。

### 三层概念对照

| 术语 | 别称 | 对应实物 |
|---|---|---|
| 关系模式 R(U) | 型 / 表结构 / 表头 | `CREATE TABLE` 语句 |
| 关系实例 r | 值 / 数据表 | 表里具体的行 |
| 元组 | 行 / 记录 | 一行数据 |
| 属性 | 列 / 字段 | 一列 |
| **度（目）** | degree | **属性个数**（本题 = 4） |
| **基数** | cardinality | **元组个数**（行数） |

### 为什么考试用字母而不用真实属性名？

因为考的是**纯形式化推理**（闭包计算、范式判定），**与业务语义无关**：
- 现实中"姓名→系名"通常不成立，但**题目给的 F 就是规定**，必须当作成立
- 用字母可避免考生靠"常识感"猜答案，只能老实算闭包

### 读题公式

```
R(A,B,C,D)  →  有哪几列   →  闭包必须推到 {A,B,C,D} 才算候选键
F = {...}   →  谁定谁     →  决定候选键、范式、分解方式
```

> 🪝 **"R 是表头（有哪些列），F 是规矩（谁定谁），元组是行，属性是列；度看列数，基数看行数。"**

## 一、函数依赖（FD）

### 1.1 定义
关系模式 R(U)，X、Y ⊆ U。若 R 的**任意两个元组**在 X 上取值相等，则它们在 Y 上也相等，称 **X 函数决定 Y**，记作 **X → Y**（X 是决定因素）。

直白理解：**知道了 X，就能唯一确定 Y。**

### 1.2 三种分类

| 类型 | 定义 | 例子 |
|---|---|---|
| **平凡 FD** | Y ⊆ X（如 AB→A） | 无实际意义 |
| **非平凡 FD** | Y ⊄ X | 正常依赖 |
| **完全函数依赖** | X→Y，且 X 的**任何真子集**都不能决定 Y | (学号,课号)→成绩，缺一不可 |
| **部分函数依赖** | X→Y，但 X 的**某个真子集**也能决定 Y | (学号,课号)→姓名（学号单独就能定） |
| **传递函数依赖** | X→Y，Y→Z，且 **Y ↛ X**（Y 不能反推 X） | 学号→系名，系名→系主任 |

> ⚠️ 传递依赖必须满足 **Y ↛ X**。若是 X↔Y（互相决定），则不算传递依赖。

### 1.3 Armstrong 公理（推理规则）

**三条基本公理**：
1. **自反律**：若 Y ⊆ X，则 X → Y
2. **增广律**：若 X → Y，则 XZ → YZ
3. **传递律**：若 X → Y，Y → Z，则 X → Z

**三条推论**（考试常用）：
4. **合并规则**：X→Y，X→Z ⟹ X→YZ
5. **分解规则**：X→YZ ⟹ X→Y，X→Z
6. **伪传递规则**：X→Y，WY→Z ⟹ WX→Z

## 二、属性闭包 X⁺（求候选键的核心工具）

### 2.1 定义
**X⁺** = 由 X 出发，用给定 FD 集能推导出的**所有属性**集合。

### 2.2 计算算法（必须背熟）

```
输入：属性集 X，函数依赖集 F
1. result = X
2. 扫描 F 中每个依赖 A → B：
      若 A ⊆ result，则 result = result ∪ B
3. 重复第 2 步，直到 result 不再变化
输出：result 即 X⁺
```

### 2.3 用途
- **求候选键**：若某属性集 X⁺ = U（全部属性），则 X 是超键
- **判断 FD 是否成立**：X→Y 成立 ⟺ Y ⊆ X⁺
- **判断无损分解**

## 三、候选键求解（必考）

### 3.1 相关概念

| 概念 | 定义 |
|---|---|
| **超键** | 能唯一标识元组的属性集（可能有冗余） |
| **候选键** | **能推出全部属性且不含多余属性**的超键（最小超键） |
| **主键** | 从候选键中人为选定的一个 |
| **主属性** | 包含在**任一候选键**中的属性（重要！） |
| **非主属性** | 不在任何候选键中的属性 |

> ⚠️ 候选键**可以有多个**；主属性看的是"任一候选键"，不是只看主键。

### 3.2 四类属性分类法（快速判定）

把每个属性按在 FD 中出现的位置分类：

| 类别 | 特征 | 结论 |
|---|---|---|
| **L 类** | 只在**左边**出现 | **必定在候选键中** |
| **R 类** | 只在**右边**出现 | **必定不在候选键中** |
| **LR 类** | **两边都**出现 | 可能在，需要验证 |
| **N 类** | **两边都不**出现 | **必定在候选键中** |

**求解步骤**：
1. 取 **L 类 + N 类**，求闭包
2. 若闭包 = U → 这就是**唯一候选键**，结束
3. 若闭包 ≠ U → 依次尝试加入 LR 类属性（1 个、2 个…），直到闭包 = U
4. **验证最小性**：去掉任一属性后若仍能推出 U，则该属性是冗余的，不是候选键

### 3.3 例题（本次诊断卷第 18 题）

**R(A, B, C, D)，F = {A→B, B→C, A→D}，求候选键。**

**第一步：分类**
- L 类：**A**（只在左边）
- R 类：**C**（只在 B→C 右边）、**D**（只在 A→D 右边）
- LR 类：**B**（在 A→B 右边、B→C 左边）

**第二步：求 L 类的闭包**
```
A⁺ = {A}                    （初始）
   → 由 A→B，得 {A, B}
   → 由 B→C，得 {A, B, C}
   → 由 A→D，得 {A, B, C, D}
A⁺ = {A, B, C, D} = U  ✓
```

**第三步：结论**
A 能推出全部属性 → **A 是候选键**。
由于 L+N 类已能推出全部属性，**不需要**加入 LR 类，故 **A 是唯一候选键**。

**主属性 = {A}**，**非主属性 = {B, C, D}**。

> ❌ 常见错误：选 **AC** 或 **AB**。虽然它们也能推出全部属性，但**含冗余**（A 单独就够了），不满足候选键的"**最小性**"要求。

> 🪝 **钩子**："**候选键 = 能推出全部属性的最小集合**。L 类和 N 类先算，够了就别加人。"

## 四、范式（Normal Form）

### 4.1 四级范式定义

| 范式 | 条件 | 解决的问题 |
|---|---|---|
| **1NF** | 每个属性都是**原子**的（不可再分） | 表中表、多值字段 |
| **2NF** | 1NF + **非主属性完全依赖**于候选键 | **部分函数依赖** |
| **3NF** | 2NF + **非主属性不传递依赖**于候选键 | **传递函数依赖** |
| **BCNF** | **所有 FD 的决定因素都包含候选键**（左边都是超键） | **主属性对码的部分/传递依赖** |

**包含关系（越往后越严格）**：
```
1NF ⊃ 2NF ⊃ 3NF ⊃ BCNF ⊃ 4NF
BCNF 一定满足 3NF，反之不成立
```

### 4.2 2NF 判定要点

> ⭐ **若候选键是"单属性"，则 2NF 自动满足**（单属性不存在真子集，谈不上"部分依赖"）。

若候选键是复合键（如 AB），则要检查：有没有非主属性只依赖 A 或只依赖 B？
- (学号, 课号) → 成绩 ⇒ 完全依赖 ✓
- (学号, 课号) → 姓名，而 学号 → 姓名 ⇒ **部分依赖** ✗ 违反 2NF

### 4.3 3NF 判定要点

检查是否存在 **X → Y → Z** 的接力（且 Y ↛ X）：
- 学号 → 系名 → 系主任 ⇒ **传递依赖** ✗ 违反 3NF

**3NF 的等价定义**：对每个非平凡 FD X→A，满足以下**之一**：
- A 是**主属性**，或
- X 是**超键**

### 4.4 BCNF 判定要点

**对每个非平凡 FD X→A，X 必须是超键**（不允许"主属性"这个例外）。

**3NF 与 BCNF 的唯一差别**：3NF 允许**主属性**对码的部分/传递依赖，BCNF 不允许。

经典反例：R(学生, 课程, 教师)，每个教师只教一门课。
FD = {教师→课程, (学生,课程)→教师}
- 候选键：(学生,课程) 和 (学生,教师)
- 主属性：学生、课程、教师（全是主属性！）
- 教师→课程：决定因素"教师"不含候选键，但**课程是主属性** → 满足 3NF，**违反 BCNF**

### 4.5 例题（本次诊断卷第 19 题）

**承上题 R(A,B,C,D)，F = {A→B, B→C, A→D}，判范式。**

**逐步判定**：
1. **1NF**？属性全原子 ✓
2. **2NF**？候选键 A 是**单属性** → 不可能有部分依赖 → **满足 2NF** ✓
3. **3NF**？检查传递依赖：
   - A→B，且 B→C ⇒ **A→B→C 是传递依赖**（B 不能反推 A）
   - → **违反 3NF** ✗
4. 结论：**属于 2NF**

> 🪝 **钩子**："**单属性键自动过 2NF**（没东西可'部分'依赖）。**看到 A→B→C 这种接力就是传递依赖 → 卡在 2NF。**"

## 五、模式分解

### 5.1 无损连接分解

分解后通过**自然连接**能恢复原关系，不产生伪元组。

**两个子模式的判定定理**：
> R 分解为 R1、R2，若 **R1 ∩ R2 → R1** 或 **R1 ∩ R2 → R2**，则为无损连接分解。

即：**公共属性必须是其中一个子模式的键**。

### 5.2 保持函数依赖

分解后各子模式上的 FD 并集，要能推出原 FD 集的所有依赖。

### 5.3 分解算法结论（考点）

| 目标 | 无损连接 | 保持依赖 |
|---|---|---|
| **3NF 分解** | ✓ 可做到 | ✓ 可做到 |
| **BCNF 分解** | ✓ 可做到 | ❌ **不一定**能保持 |

> 🪝 **钩子**："**3NF 两全其美**（无损+保依赖）；**BCNF 更严格但要牺牲函数依赖**。"

### 5.4 例题（题库第 3 题）

**将 R(A,B,C,D) 分解为 3NF（无损连接 + 保持依赖）：**

**答案：R1(A,B,D)、R2(B,C)**

**验证**：
- 保依赖：R1 保留 A→B、A→D；R2 保留 B→C ✓
- 无损：R1 ∩ R2 = **{B}**，而 B 是 R2 的键（B→C）✓

分解方法：**每个 FD 的左边属性 + 右边属性合成一个子模式**，再检查无损性。

## 六、完整解题套路（考试按这个顺序走）

```
第 1 步：列出所有属性，把 FD 按左边分组
第 2 步：属性分类（L / R / LR / N）
第 3 步：L + N 求闭包 → 得到候选键（不够再逐个加 LR）
第 4 步：确定主属性 / 非主属性
第 5 步：判范式
        单属性键 → 直接到 2NF，查传递依赖
        复合键   → 先查部分依赖（2NF），再查传递依赖（3NF）
第 6 步：若要分解 → 每个 FD 建一个子模式 → 验无损（公共属性是不是键）
```

## 七、常见陷阱清单

| 陷阱 | 正解 |
|---|---|
| 候选键选了含冗余的集合（如 AC） | 候选键必须**最小** |
| 认为候选键只有一个 | **可以有多个**；主属性看"任一候选键" |
| 单属性键还去查部分依赖 | 单属性键**自动满足 2NF** |
| 把"互相决定"当传递依赖 | 传递依赖要求 **Y ↛ X** |
| 分不清 3NF 和 BCNF | 差别只在**主属性**的依赖 |
| 以为 BCNF 分解也能保依赖 | **BCNF 分解不一定保持函数依赖** |
| 无损判定用错方向 | 公共属性必须是**其中一个子模式的键** |

## 八、其他常考的数据库知识点（同章）

- **事务 ACID**：原子性、一致性、**隔离性（并发不干扰）**、持久性
- **隔离级别**：读未提交 → 读已提交 → **可重复读**（解决不可重复读）→ 串行化；可重复读仍有**幻读**
- **视图**：虚表不存数据；**只有简单视图可更新**（含 JOIN/聚合/DISTINCT 的不可更新）
- **E-R 转关系**：**M:N 联系必须独立建表**，主键为两端主键的组合；1:N 可合并到 N 端
- **索引**：加速 SELECT，拖慢写操作，**不是越多越好**（建议 ≤6 个）
- **CAP**：一致性 / 可用性 / **分区容错性**；分布式必选 P，在 CP 与 AP 间权衡
- **NoSQL**：Neo4j（图，社交关系）、Redis（KV/缓存）、MongoDB（文档）、HBase（列族）
- **数据仓库四特征**：面向主题、集成、**相对稳定（非实时）**、反映历史变化
- **主键/外键**：主键非空唯一、一张表只能一个主键；外键引用对端主键或唯一键，自身**不要求唯一**
