# 六大质量属性战术速查表

> 私人复习文件（`.study/`）。对应案例题"列出 N 条战术"题型与论文"架构决策"论述。
> 用法：**背"类别名 + 落地形式"两层**——只写落地说不出类别，会丢一半分。

---

## 一、可用性（Availability）战术

### ① 错误检测（发现故障）

| 战术 | 机制 | 主动权 |
|---|---|---|
| **Ping/Echo** | 监控端周期性发 Ping → 被监控端回 Echo → 超时未收到即判故障 | **监控端主动** |
| **心跳 Heartbeat** | 被监控端周期性发简短通告 → 监控端超时未收到即判故障 | **被监控端主动** |
| 异常检测 | 监控组件运行指标，异常即告警 | — |
| 命令/响应 | 监控端发命令，被监控端应答（如 SNMP） | 监控端 |

> ⚠️ **两者都是架构战术（软件层面），不是 ICMP ping 命令；不限协议。**

### ② 错误恢复（故障后恢复）

| 战术 | 说明 |
|---|---|
| **主动冗余（双活）** | 所有副本同时处理请求，故障时无缝接管 |
| **被动冗余（主备）** | 主节点工作，备节点待命，故障时切换 |
| **备用（冷备）** | 备份组件平时不运行，需要时启动 |
| **检查点/回滚** | 定期保存状态，故障后从检查点恢复 |
| **重试** | 对可恢复的失败自动重试 |
| **降级** | 关闭非核心功能，保住核心服务 |
| **忽略故障** | 容错设计，局部故障不影响整体 |

### ③ 错误预防（避免故障发生）

移除服务（下线维护）、事务（原子性保证）、进程监视器、预防性维护

## 二、性能（Performance）战术

### ① 资源需求控制（少用资源）

| 战术 | 说明 |
|---|---|
| **减少计算** | 算法优化、预计算、结果缓存 |
| **减少开销** | 减少中间层、精简协议、合并调用 |
| **管理事件率** | 限流、采样、降频 |
| **控制资源使用** | 限制并发数、队列长度 |

### ② 资源管理（更高效地用资源）

| 战术 | 说明 |
|---|---|
| **引入并发** | 多线程、多进程、并行处理 |
| **缓存** | 本地缓存（Caffeine）、分布式缓存（Redis） |
| **异步** | 消息队列削峰、异步落库 |
| **资源池** | 连接池、线程池、对象池 |
| **调度策略** | FIFO、优先级、轮转、最短作业优先 |
| **负载均衡** | 分流到多节点 |
| **分区/分片** | 数据分库分表、按 key 哈希 |
| **批处理** | 攒批处理减少往返 |
| **增加资源** | 横向扩容 |

## 三、安全性（Security）战术

### ① 抵抗攻击

| 战术 | 说明 |
|---|---|
| **认证** | 验证"你是谁"（JWT、OAuth、mTLS、双因素） |
| **授权** | 控制"你能做什么"（RBAC、最小权限） |
| **数据加密** | 传输加密（TLS）、存储加密（AES） |
| **完整性校验** | 数字签名、摘要、MAC |
| **限制暴露** | 减少攻击面、隐藏内部结构 |
| **限制访问** | 网络隔离、防火墙、白名单 |

### ② 检测攻击
入侵检测（IDS）、审计追踪（日志留痕）

### ③ 从攻击中恢复
恢复（备份还原）、识别攻击者（取证）

## 四、可修改性（Modifiability）战术

| 类别 | 战术 |
|---|---|
| **降低耦合 / 提高内聚** | 模块化、封装、分层、信息隐藏 |
| **延迟绑定** | 配置文件、运行时注册、多态、**依赖注入（DI）**、插件化 |

| **标准化** | 统一协议、统一数据模型、API 版本管理 |

## 八、考试用法（关键）

### 案例题问法
> "针对【某质量目标】，列出至少 3 条战术（注明所属类别），并说明在本架构中的落地形式。"

### 得分公式
```
每条战术 = 【类别名】 + 落地形式
```

**✅ 满分写法**：
> "**①【资源池】战术**：提升 Flink 并行度与 Kafka 分区数至 100，使 20 万点/秒的告警计算并行处理，降低端到端延迟。"

**❌ 扣分写法**：
> "用了 Kafka" ← 只有落地形式，没有类别
> "用了资源池战术" ← 只有类别，没有落地形式

### 论文用法
在"架构设计"段落写：
> "针对高并发写入瓶颈，我采用了**性能战术中的异步与资源池组合**：引入 Kafka 削峰、数据库连接池调优，使峰值 QPS 从 X 提升至 Y。"

## 九、高频记忆钩子

> **可用性**：**检测（Ping/Echo、心跳）+ 恢复（冗余、回滚、重试、降级）+ 预防（事务、移除服务）**
> **性能**：**少用（减少计算/开销/事件率）+ 巧用（并发、缓存、异步、资源池、分区）**
> **安全**：**防（认证、授权、加密、完整性）+ 测（入侵检测、审计）+ 恢复**
> **可修改性**：**解耦 + 延迟绑定（配置化、DI、插件化）**
> **可测试性**：**记录回放、接口分离、内部监控、抽象数据源**
> **易用性**：**撤销、取消、聚合、任务模型、状态显示**

## 十、易错点清单

| ❌ 常见错误 | ✅ 正确 |
|---|---|
| 把 Ping/Echo 写成"发送 ICMP 包" | 它是**架构战术**：监控端主动探测，被监控端回 Echo |
| 说心跳是"请求-响应" | 心跳是**单向通告**，被监控端主动发 |
| 论证只写一个维度 | 至少 3 个维度，每维度用"【维度名】+ 论证" |
| 把"加密"当纯优点 | 加密是**权衡点**：安全(+) vs 性能(−) |
| 战术不写类别 | 必须"【类别】+ 落地形式"两层齐全 |
