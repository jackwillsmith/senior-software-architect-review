## 一、K05 软件测试 · CMMI · 维护（错 10 次，最高频）

### 1. CMMI 五级（错 4 次）
**正确**：初始(L1) → **已管理(L2)** → **已定义(L3)** → 量化管理(L4) → 优化(L5)
- L2 已管理：**项目**级管好自己（需求/计划/监控/配置）
- L3 已定义：**组织**级统一标准过程，项目裁剪执行
- L4 量化管理：用**数据/SPC 统计过程控制**管过程
- L5 优化：持续改进、缺陷预防
- **陷阱**：老 CMM 的 L2 叫"可重复"，CMMI 改名"已管理"
- **钩子**：项目2 / 组织3 / 数据4 / 改进5

### 2. 软件维护四类占比（错 4 次）
| 类型 | 内容 | 占比 |
|---|---|---|
| **完善性** Perfective | 加功能、优化性能 | **~60%（最多）** |
| **适应性** Adaptive | 适应环境变化（OS/换库） | ~25% |
| **改正性** Corrective | 修 bug | ~20% |
| **预防性** Preventive | 重构、补测试防未来 | ~5% |
- **钩子**：完(6) > 适(2.5) > 改(2) > 预(0.5)；名称是"预防性"，**没有"计划维护"**

### 3. 集成测试策略（错 1 次）
- **自顶向下**：先测主控/决策结构，下层未完成需 **Stub 桩**；**关键计算模块在底层 → 验证晚**
- **自底向上**：先测叶子模块，需 **Driver 驱动**模拟上层；主控逻辑最后验证
- **大爆炸**：一次性全集成，调试困难
- **三明治**：上下同时向中间集成

### 4. 可靠性指标（错 1 次）
- **MTTF** = 平均无故障运行时间（活多久才坏）
- **MTTR** = 平均故障修复时间（坏多久修好）
- **MTBF** = 平均故障间隔 = MTTF + MTTR
- **可用性 A = MTTF / (MTTF + MTTR)**
- 四个 9（99.99%）= 年宕机 **52.6 分钟**

### 5. 测试其他
- 黑盒/白盒与执行者无关（黑盒常由独立测试/用户做，白盒由开发做）
- α 测试：开发方场地受控环境；β 测试：用户实际环境
- 判定表/因果图 → 多条件组合逻辑；等价类 → 输入域大；边界值 → 数值范围
- McCabe 圈复杂度 **V(G) = E − N + 2** = 判定节点数 + 1
- 净室软件工程：形式化+正确性验证，适合**航天/医疗/核电**，**不适合需求频繁变化的互联网**

## 二、K17 知识产权（错 8 次）

| 考点 | 正确 |
|---|---|
| 发明专利保护期 | **自申请日**起 **20 年**（不是授权日） |
| 实用新型 | 自申请日起 10 年 |
| 外观设计 | 自申请日起 **15 年**（2021 年由 10 年改） |
| 商标 | 10 年，**期满前 12 个月可续展，无限次** |
| **专利期满** | **不能续展，直接终止** |
| 著作权（自然人） | 终身 + 死后 50 年 |
| 著作权（法人/职务） | 首次发表后 50 年 |
| 软件著作权产生 | **自创作完成之日自动产生**（登记≠产生，只是权属证据） |
| 专利申请原则 | **先申请制**（不是先发明制） |
| 商业秘密 | 秘密性+价值性+保密措施；**无固定期限**（保密即永久），无需登记 |
| 国标分类 | **GB 强制 / GB/T 推荐 / GB/Z 指导性技术文件**（无"商业性"） |
| ISO 9000 / 14000 / 27001 | 质量 / 环境 / **信息安全(ISMS)** |
| 著作权不保护 | **思想、算法、功能本身**（只保护表达：代码、文档） |
| 不受著作权保护 | 法律法规、时事新闻、通用数表公式 |
| 合理使用 | 为**自己使用**制作备份、为研究学习反向工程 |

### 职务作品（错 2 次，顽固点）
| | 一般职务作品 | **特殊职务作品**（软件/工程设计图/地图） |
|---|---|---|

### 委托开发
- **合同约定优先**；**未约定归受托方**（开发者）

## 三、K22 英语阅读（错 8 次）

| 术语 | 含义 |
|---|---|
| **provision** | 按需供给云资源 |
| **elasticity** | 弹性（自动扩缩容）≠ virtualization |
| **upfront cost** | 前期/一次性投入（pay-as-you-go 降低的是它） |
| **orchestration** | 容器编排（K8s 的标准定语） |
| **monolithic** | 单体（微服务的对立面） |
| **independently deployable** | 独立部署（微服务看家本领） |
| **service mesh** | 服务网格：东西向、服务发现/负载均衡/**熔断** |
| **API gateway** | 网关：南北向、路由/鉴权/限流 |
| **data consistency** | 数据一致性（Saga/TCC 解决分布式事务） |
| cloud concerns | data **privacy** + regulatory compliance + vendor lock-in |
- **钩子**：东西向找 mesh，南北向找 gateway

## 四、K03 UML（错 6 次）

| 考点 | 正确 |
|---|---|
| UML 2.x 图数量 | **14 种**（结构 7 + 行为 7）；UML 1.x 才 9 种 |
| 结构图 7 种 | 类图、对象图、构件图、部署图、包图、组合结构图、制品图 |
| 行为图 7 种 | 用例图、活动图、状态机图、时序图、通信图、交互概览图、时间图 |
| 继承（泛化） | 实线 + **空心**三角 |
| 实现 | 虚线 + 空心三角 |
| **聚合** | **空心**菱形，弱所属，部分可独立存在 |
| **组合** | **实心**菱形，强所属，**整体销毁部分随之销毁** |
| 关系强度（弱→强） | **依赖 < 关联 < 聚合 < 组合** |
| 依赖 | 最弱，临时关系（方法参数/局部变量） |
| 用例图元素 | 参与者 + 用例 + 系统边界 + 关系（**类不属于用例图**） |
| include / extend | include **必须执行**；extend **可选扩展** |

## 五、K08 软件过程模型（错 4 次）

- **RUP 四阶段**：**初始 → 精化 → 构建 → 移交**（官方译名，不是"精华"）
  - 初始：定范围/可行性
  - **精化**：**建立可执行架构基线 + 识别主要风险**（必考）
  - 构建：写完所有功能；移交：交付上线
- **螺旋模型**：每轮含**风险分析**，适合大型高风险项目
- **瀑布**：单向、文档驱动、不响应变化
- **原型**：需求不明确时用
- **敏捷**：拥抱变化，但**不摒弃文档**（"高于"≠"取代"）

## 六、C01 案例 ATAM（错 4 次，已转稳定）

- **ATAM 全称** = Architecture Tradeoff Analysis Method（**架构权衡分析方法**）
- **四类点**：敏感点 / 权衡点 / 风险点 / 非风险点
- **判别表**：
  | 关键词 | 类别 |
  |---|---|
  | "一升一降""属性冲突" | **权衡点** |
  | "可能…""尚未验证" | **风险点** |
  | "对某属性影响显著"（单属性） | **敏感点** |
  | "已验证""有依据" | **非风险点** |
  | "与架构无关" | 不纳入 ATAM |
- **纯增益方案**（如 CDN 降延迟）**不是权衡点**
- **六元组**：刺激源（谁）→ 刺激（做啥）→ 环境（啥背景）→ 制品（谁挨打）→ 响应（咋应对，系统行为）→ 响应度量（数字+单位）
- **答题纪律**：题干列几条决策就答几条；几个小问就答几问（漏答=丢分）

## 七、K01 操作系统（错 3 次）

- **进程 vs 线程**：进程=资源分配单位，线程=调度单位；**线程可共享内存直接通信**（不是"不能通信"）；线程切换开销小
- **死锁四条件**：互斥 + 占有且等待 + **不可抢占** + 循环等待（**没有"可抢占"**）
- **银行家算法** = 死锁**避免**（安全序列判定），不是检测恢复
- **资源有序分配** → 破坏**循环等待**
- 抖动 = 频繁缺页换页；OPT 需预知未来无法实现；SJF 导致长作业饥饿
- 页式地址转换需**页表 + 快表(TLB)**

## 九、K02 网络协议（错 2 次）

- **网络层**：IP、ICMP、ARP、IGMP
- **传输层**：TCP、UDP（**不是网络层**）
- **应用层**：HTTP、FTP、SMTP、DNS
- **链路层**：PPP、Ethernet
- 端口：DNS **53**、POP3 **110**、IMAP **143**、HTTP 80、HTTPS 443、FTP 20/21、SSH 22、SMTP 25、SNMP 161/162
- TCP 只支持一对一，**不支持广播/组播**；UDP 支持一对一/一对多/多对多

## 十、K04 架构风格（错 2 次）

| 风格 | 特征 | 案例 |
|---|---|---|
| **数据流** | 数据流经处理单元 | **批处理**、管道-过滤器 |
| **仓库** | 中央共享数据结构 | **数据库、黑板、编译器符号表** |
| **调用返回** | 主控调用子程序 | 主程序-子程序、面向对象、分层 |
| **独立构件** | 进程通信/事件 | **事件驱动**、发布订阅 |
- 分层最大问题 = 性能（请求穿透多层）
- MVC 价值 = 职责分离、多视图同步
- 黑板用于语音识别/AI 推理，**不是电商订单**

## 十一、其他单点错题

| 考点 | 正确 |
|---|---|
| K16 需求工程五活动 | **获取 → 分析 → 规约 → 验证 → 管理**（没有"需求实现"） |
| K16 非功能需求 | 是**架构的关键驱动力（ASR）**，不是"仅实现阶段考虑" |
| K16 需求获取 | 问卷=大量分散用户；访谈=深度；观察=说不清流程；JAD=相关方集中开会 |
| K12 微服务粒度 | **不是越小越好**，围绕**限界上下文**划分 |
| K18 Cache 映射 | **全相联命中率最高**（不是低），但硬件复杂成本高；直接映射命中率低但简单 |
| K10 候选键 | 求属性闭包：A→B→C、A→D ⇒ A+ = {A,B,C,D} ⇒ **A 是候选键** |
| K10 范式 | 单属性键无部分依赖 ⇒ 2NF；有传递依赖 A→B→C ⇒ 不到 3NF |

## 十二、系统性答题问题（比知识更致命）

1. **否定型题干全错**（4/4 错）：题干含"错误/不包括/不属于"时，误选成正确项
   - **固定动作**：圈否定词 → 默念"选错的那个" → 答完反问"反过来问答案会变吗"
2. **审题方向反**：UML 关系强度"从弱到强"答成从强到弱
3. **跳题/漏答**：案例问题 2 两次未答；3 个决策只答 1 个
   - **固定动作**：先数题干有几个决策、几个小问，答完清点
4. **精确术语漂移**：预防性→"计划"、精化→"精华"、MTBF 混 MTTR
5. **疲劳后抢答**：连续答题超 15 题后出现词形猜测（monotonically 等）
