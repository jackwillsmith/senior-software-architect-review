## 1. 数据库

### 1.1 范式

| 范式 | 核心要求 |
|---|---|
| 1NF | 属性不可再分，没有重复组 |
| 2NF | 在 1NF 基础上，消除非主属性对码的**部分函数依赖** |
| 3NF | 在 2NF 基础上，消除非主属性对码的**传递函数依赖** |
| BCNF | 在 3NF 基础上，进一步消除主属性对码的部分和传递函数依赖 |

**记忆：**

- 1NF：列不可分
- 2NF：消除部分依赖
- 3NF：消除传递依赖
- BCNF：更严格，主属性也不能有部分/传递依赖

### 1.2 关系代数

| 运算 | 符号 | 作用 |
|---|---|---|
| 选择 | σ | 按条件筛选**元组（行）** |
| 投影 | π | 选择指定**属性（列）** |
| 连接 | ⋈ | 按条件组合两个关系 |
| 除法 | ÷ | 常用于“包含全部”类查询 |

**易错：** 选择是选行，投影是选列。

### 1.3 E-R 图符号

| 符号 | 含义 |
|---|---|
| 矩形 | 实体 |
| 椭圆 | 属性 |
| 菱形 | 联系 |
| 下划线 | 主键属性 |

### 1.4 码的概念

| 概念 | 含义 |
|---|---|
| 超码 | 能唯一标识元组，但可能包含多余属性 |
| 候选码 | 能唯一标识元组，且不包含多余属性 |
| 主键 | 从候选码中选定的一个 |
| 外键 | 参照另一个关系的主键/候选码 |

**易错：** “不包含多余属性” → 候选码；“选定的一个” → 主键。

### 1.5 数据库设计阶段

1. 需求分析：收集和分析用户需求。
2. 概念设计：形成 E-R 图等概念模型。
3. 逻辑设计：将 E-R 图转换为关系模式，并进行规范化。
4. 物理设计：确定存储结构、索引、分区等。

**记忆：** E-R 图是概念设计的产物，E-R 转关系模式属于逻辑设计。

## 2. 软件可靠性

### 2.1 串联系统

所有组件都正常，系统才正常：

\[
R = R_1 \times R_2 \times \cdots \times R_n
\]

特点：组件越多，可靠性越低。

### 2.2 并联系统

至少一个组件正常，系统就正常：

\[
R = 1 - (1-R_1)(1-R_2)\cdots(1-R_n)
\]

特点：组件越多，可靠性越高。

### 2.3 至少 k / n 正常

\[
R = \sum_{i=k}^{n} C(n,i) \cdot R^i \cdot (1-R)^{n-i}
\]

示例：4 个部件，每个可靠度 0.9，至少 3 个正常：

\[
R = C(4,3) \times 0.9^3 \times 0.1 + C(4,4) \times 0.9^4
\]

\[
R = 4 \times 0.729 \times 0.1 + 0.6561 = 0.9477
\]

### 2.4 常见易混

| 场景 | 公式 | 示例 |
|---|---|---|
| 两个 0.9 串联 | \(0.9 \times 0.9\) | 0.81 |
| 两个 0.9 并联 | \(1 - 0.1^2\) | 0.99 |
| 4 个 0.9 全并联 | \(1 - 0.1^4\) | 0.9999 |
| 4 个 0.9 至少 3 正常 | 组合求和 | 0.9477 |
| 两个串联子系统，每个内部两并联 | 先并联再串联 | 0.99 × 0.99 = 0.9801 |

## 3. 计算机系统与操作系统

### 3.1 MIPS

\[
MIPS = \frac{主频}{CPI}
\]

主频单位通常为 MHz。  
示例：2GHz = 2000MHz，CPI = 4：

\[
MIPS = \frac{2000}{4} = 500
\]

### 3.2 进程与线程

| 对比项 | 进程 | 线程 |
|---|---|---|
| 基本单位 | 资源分配的基本单位 | CPU 调度的基本单位 |
| 地址空间 | 独立 | 同一进程内共享 |
| 切换开销 | 较大 | 较小 |
| 通信方式 | IPC、共享内存等 | 直接共享进程资源 |

**易错：** 进程是资源分配单位，线程是调度单位，不要反。

## 4. 软件测试

| 类型 | 关注点 |
|---|---|
| 黑盒测试 | 不关心内部实现，根据输入输出设计用例 |
| 白盒测试 | 关注内部逻辑、语句、分支、路径覆盖 |
| 静态分析 | 不运行程序，分析代码、文档等 |
| 代码审查 | 人工检查代码质量、规范与缺陷 |

**记忆：** 黑盒看外部行为，白盒看内部结构。

## 5. 信息安全：STRIDE

| 威胁 | 英文 | 对应安全属性 |
|---|---|---|
| 假冒 | Spoofing | 认证 |
| 篡改 | Tampering | 完整性 |
| 抵赖 | Repudiation | 不可抵赖性 |
| 信息泄露 | Information disclosure | 保密性 |
| 拒绝服务 | Denial of service | 可用性 |
| 提权 | Elevation of privilege | 授权 |

**高频易错：** Tampering → 完整性，不是不可抵赖性。

## 6. 架构描述语言 ADL

ADL（Architecture Description Language）主要用于描述：

- 构件 Component
- 连接件 Connector
- 架构配置 Configuration

**易错对比：**

- 类、对象、继承 → 面向对象模型 / 类图
- 用例、参与者、场景 → 用例模型
- 表、视图、索引 → 数据库模型
- 构件、连接件、配置 → ADL

## 7. 应用数学：组合概率

### 7.1 组合数公式

\[
C(n,k) = \frac{n!}{k!(n-k)!}
\]

### 7.2 典型题

5 个白球、3 个黑球，任取 2 个，恰好 1 个黑球：

总取法：

\[
C(8,2) = 28
\]

有利取法：

\[
C(3,1) \times C(5,1) = 15
\]

概率：

\[
P = \frac{15}{28}
\]

**方法：** 分别算“总情况数”和“满足条件的情况数”，再相除。

## 10. 复习建议

1. 先复习数据库五大点：范式、关系代数、E-R 图、候选码、设计阶段。
2. 再做可靠性计算专项：串联、并联、混联、至少 k/n。
3. 复习 OS 与计算机系统：进程/线程、MIPS、页面置换、死锁。
4. 复习软件测试：黑盒/白盒、单元/集成/系统/验收。
5. 背 STRIDE 表、ADL 三要素。
6. 每天过 10 个专业英语高频词。
7. 一周后重做本套 75 题，重点检查本次 15 道错题。
